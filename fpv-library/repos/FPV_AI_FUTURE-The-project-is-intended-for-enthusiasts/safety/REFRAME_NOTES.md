# safety/verifier.py — заметки по ПЕРЕОСМЫСЛЕНИЮ (TODO интегратору)

`verifier.py` перенесён БЕЗ ИЗМЕНЕНИЙ из наземной системы CUAS (`cuas/g2u`).
Там он выполнял ПРОТИВОПОЛОЖНУЮ задачу и использовать его как есть в кинетическом
блоке НЕЛЬЗЯ.

## Что он делает в CUAS (исходный смысл)

Блокирующая анти-оружейная калитка наземной системы: «земля никогда не приказывает
БПЛА поражать». Список `FORBIDDEN_FIELD_VALUES` отвергает любое сообщение,
содержащее `engage`, `intercept`, `jam`, `attack`, `kinetic`, `fire`, `destroy`,
`neutralize`, `ram`, `strike`, `detonate`, `munition` и т.п. — подстрочным
поиском, паранойяльно. То есть в исходном виде он запрещает САМ кинетический
блок 03.

## Что переиспользуется как есть (реальное ядро)

- Конверт подписи/проверки Ed25519 (PyNaCl/cryptography) с HMAC-SHA256
  dev-fallback (`key_id` `hmac:...`).
- Канонический JSON для подписи (`canonical_payload`).
- Журнал JSONL (`publish_event` / `replay_events`).
- Загрузка и валидация JSON-схем (`schemas/`).
- Рекурсивный обход нагрузки (`_scan_forbidden`).

## Что ОБЯЗАН переделать интегратор

1. **Инвертировать семантику.** Из «блокировать любой кинетический токен» в
   калитку АВТОРИЗАЦИИ-ВЗВЕДЕНИЯ: кинетическое намерение по умолчанию
   ЗАБЛОКИРОВАНО и разблокируется ТОЛЬКО при предъявлении валидного,
   подписанного, неистёкшего `operator_authorization.v1`.
2. **Привязать к авторизации.** Kill-ветка проходит, только если присутствует
   `operator_authorization.v1` с: подписями двух операторов, `physical_keypress_recorded=true`,
   `roe_engine_pass=true`, приемлемым `civcas_estimate`, не истёкшим `expires_at_utc`,
   и подтверждением цели как неотвечающей угрозы.
3. **Сохранить fail-closed.** Любая неполнота/ошибка проверки => БЛОКИРОВКА.
   Производство ОБЯЗАНО использовать Ed25519 (не HMAC-fallback).
4. **Привязать к `engagement_handoff`** (контракт ещё предстоит спроектировать,
   см. `../../contracts/README.md`).

До выполнения этих шагов файл присутствует как ядро безопасности, но НЕ является
готовой кинетической калиткой.
